# 证书安装与 VPN

## 61 版：兼容安装入口

用户同意试用公网清单方案后，在下载详情新增独立的“兼容安装”。该入口启动仅绑定 `127.0.0.1` 的 HTTP 服务提供本机 IPA 和浏览器安装页面，以公网 HTTPS 生成的 XML 作为 `itms-services` 清单，不检查或使用本机根证书。清单服务用 Sites 部署在 <https://ssstore-install-manifest.kkkk0615.chatgpt.site>。

点击安装后，先检查本机 HTTP 连接，再通过不含账号凭据、Cookie 或持久缓存的临时 URLSession 请求公网清单。预检校验 Bundle ID、IPA 内部 `CFBundleVersion`、标题及唯一 IPA 地址完全一致，拒绝登录页、错误页、替换安装包或版本不符的清单。获得持续后台执行授权后才打开 Safari，保留原生安装链接和心跳日志。分段发送及完成判断沿用 60 版的覆盖范围记录。

元数据读取在后台线程进行，只读取主应用的 Info.plist，最大 2 MiB；不解压整个 IPA。中文名称、加号和嵌套 IPA URL 分别正确编码。清单服务只收到应用名称、Bundle ID、内部版本和随机本机下载地址，不接收账号、许可证或 IPA 文件。公网服务可能记录这些请求 URL。

已确认服务部署成功且访问模式为 public，Worker 本地测试通过。当前云端探测收到托管层 HTTP 403 / error code 1010。App 会显示预检的具体 HTTP 错误并在日志记录服务错误码。真实手机上的连通和系统安装仍待验证，不能将本版描述为已确认修复 VPN 下安装。该方式获取清单需要互联网，蜂窝网络即可；本机包传输仍可能受 VPN 路由策略影响。

## 60 版真机复测结论（2026-11-10）

VPN 始终开启时，系统已授予持续后台执行任务，Safari 在点击安装后仍连续收到心跳响应，直到用户返回 App。因此本次失败可排除后台服务被挂起。系统清单请求仍未进入 HTTP 路由，故不能把“无法连接 localhost”进一步判定为某个具体 TLS 错误或 VPN 路由错误。

Apple 从 iOS 27 起对 `appstored` 等选定系统进程执行更严格的 TLS 要求：[Apple 网络环境说明](https://support.apple.com/en-gb/126655)。当前固定的 swift-nio-ssl 2.36.0 / BoringSSL 已支持 TLS 1.3，并在 TLS 1.2 客户端请求时协商 EMS；不能仅凭新策略就宣称是缺少 EMS。修改本 App 的 ATS 例外也不能修改系统安装器的策略。

后续用户已同意试用，61 版接入[公网清单后端](../tools/installation-manifest/README.md)，参考 Feather 的 semi-local 数据流，验证范围见上文。

## 60 版：后台执行与可区分的请求日志

59 版真机日志显示：App 的系统信任检查及 HTTPS 预检成功，Safari 读取了安装页面，但系统安装清单的请求没有进入 HTTP 路由。服务在用户返回 App 后离开安装页面才关闭，因此这个关闭操作不是此前连接失败的起点。`favicon.ico` 的 404 与安装失败无关，60 版改为返回空响应。

这些日志尚不能区分 App 后台挂起、系统安装器的证书策略或 VPN 路由。App 的信任检查成功不等于系统安装器也一定接受证书。

60 版为证书安装申请 `BGContinuedProcessingTask`（iOS 26+），收到实际执行授权后才打开 Safari；拒绝授权时留在 App 提示。旧系统保留短时后台任务并检查是否获准。日志记录提交、实际授权、停止、前后台切换与短时预算。安装页面每 3 秒在可见时向本机服务发出心跳，同时记录页面就绪和安装按钮点击；点击上报不等待网络，不拦截或替换原生 `itms-services` 链接。

IPA 的成功响应按实际 `Content-Range` 合并覆盖范围。HEAD、小段探测和重复范围不会被当成整个包发送完成，连接中断允许系统重试；整个包发送完、用户退出页面或系统停止任务时结束后台任务。“发送完成”只代表服务端发送完数据，不代表设备已安装应用。

重签名时需同步保留 `BGTaskSchedulerPermittedIdentifiers` 中的 `$(PRODUCT_BUNDLE_IDENTIFIER).installation.*`。这次改动补上后台执行保护并增加诊断，不能代替 Safari、系统安装器、蜂窝网络和 VPN 组合的真机验证，暂不宣称证书安装已完全修复。未接入外部清单服务，IPA 和诊断请求仍在本机。

## 57 版：本机 HTTPS 兼容入口

56 版收到用户反馈：Safari 可打开页面，但点击安装后立即显示“无法连接 127.0.0.1”，App 仍显示“准备安装”。这表示清单请求没有进入 App 的路由处理，截图不足以判定具体的 TLS 或系统安装器错误。

57 版尝试将安装页面、清单、图标和 IPA 改为 `https://localhost:<端口>/…`，本地服务同时监听 `127.0.0.1` 和 `::1`，服务器证书覆盖两个 IP 和本机名称 `localhost`。它不依赖 `qaq.wiki` 或其他外部域名解析，仍保留 TLS 校验。

已在 56 版安装并信任本机 CA 的设备，升级时只换发服务器证书，保留同一根证书、钥匙串记录和描述文件标识；正常情况下无需重新安装描述文件。首次使用者按下文安装。
清单 URL 完整编码后嵌入 `itms-services` 的 `url` 参数，保留 HTTPS、端口和内层查询参数。新增“等待系统获取安装清单”状态、请求日志和后台时间结束提示，以区分请求没有到达与服务后台时间耗尽。HTTPS、证书和本机名称兼容性测试不能替代真实 iOS 系统安装器测试，完整效果仍待设备验证。

## 首次安装本机证书

本机证书描述文件通过 `http://127.0.0.1:<端口>/ssstore-loopback.mobileconfig` 提供；安装清单和 IPA 始终使用 HTTPS。描述文件下载地址与系统安装清单地址是不同的地址。
这一条备用安装路径不需要配对记录、局域网或 Wi-Fi；使用蜂窝网络也可打开本机服务，已下载的 IPA 不会上传到外部服务器。

首次使用需要安装新证书：

1. 进入下载详情 → 证书安装 → 安装本机证书，允许下载描述文件。
2. 在系统设置中安装“ssstore 本机安装证书”描述文件。
3. 前往设置 → 通用 → 关于本机 → 证书信任设置，为页面上显示的 `ssstore Loopback CA <编号>` 启用完整信任。
4. 返回 App，点击安装，再在浏览器和系统提示中确认。

旧版 `Asspp Local Installation CA` 不适用于新 IP 证书。每台设备本地生成 CA 和服务器私钥，以“仅本设备、首次解锁后可用”方式存入钥匙串；安装包和配置描述文件均不包含私钥。
服务器证书接近到期时会换发，保留同一 CA。CA 本身接近到期或钥匙串身份丢失时，需要重新安装并信任新证书；不要根据旧证书的开关判断新证书已受信任。
App 的检查使用系统证书信任，不忽略证书错误，也不把自己的 CA 自动添加为可信锚点。

这个改动移除了域名解析和域名代理规则的影响，目的是允许保持 VPN 开启且不新增规则。它无法替第三方 VPN 修改路由，也不能保证强制接管回环 IP 或拦截本地 HTTP/HTTPS 的 VPN 一定可用。蜂窝网络、VPN 开启时的 Safari / 系统安装完整流程仍需真机验证。

## 55 版及以前

旧版使用 `app.localhost.qaq.wiki`。Loon 的原有直连方法仅用于旧版本：

```ini
[Host]
app.localhost.qaq.wiki = 127.0.0.1

[Rule]
DOMAIN,app.localhost.qaq.wiki,DIRECT
IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
```

规则放在可能匹配的代理规则之前，并在 HTTPS 解密设置中排除该域名。
参考：[Loon DNS 映射](https://github.com/Loon0x00/LoonManual/blob/master/docs/cn/hostmap.md)。
